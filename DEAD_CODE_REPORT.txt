================================================================================
PART 1 - WHY MOST "UNUSED" CODE WAS *NOT* REMOVED  (read this first)
================================================================================

This project loads instrument drivers dynamically. scanner/scanner.py:47 and
scanner/plugin_switcher.py:47-58 use importlib + getattr() to load an arbitrary
.py file chosen by the user at runtime and instantiate whatever ProbePlugin /
MotionController subclass it finds inside.

Consequence: EVERY module under scanner/Plugins/ has zero static references,
and every method on those classes (connect, disconnect, get_axis_units,
scan_trigger_and_wait, ...) looks unused to a static analyser. They are not
dead -- they are the plugin interface. vulture reported ~120 such "unused
class / unused method" hits; all were rejected.

The same reasoning protects:
  * Qt event overrides    - wheelEvent, paintEvent, drawForeground,
                            focusInEvent, hasHeightForWidth, heightForWidth.
                            Called by the Qt event loop, never by name.
  * Auto-generated files  - gui/ui_scanner.py and gui/ui_scanner_plotter_version.py
                            carry "WARNING! All changes made in this file will be
                            lost when recompiling UI file!". They contain ~24
                            unused PySide6 imports each (pyside6-uic always emits
                            the full import block). Editing them would be undone
                            by the next uic run, so they were left alone.
  * Hardware register tables - the MUXOUTCTL_* / GPIOL* / GPIOH* constants in
                            scanner/Plugins/fmcw_connection/radarControl.py, the
                            TINYG_STAT_* constants in tinygMotor.py and the
                            OFF/ON/BR/RS/ERR codes in geckoInstructions.py are
                            unreferenced but document the wire protocol. Kept.

The rule applied throughout: code was removed only when it is unreachable even
if its own module is in active use.

================================================================================
PART 4 - CAVEATS / WHAT TO RE-CHECK
================================================================================

4.1  No test suite exists in this repository, and the application needs a VNA,
     a motion controller and Qt to start, so the cleanup could not be validated
     by running it. Validation was static: flake8 F-series clean, vulture
     re-run, and every touched file byte-compiled. Before relying on this
     branch, do one manual smoke run: launch test_scanner_gui.py, connect a
     motion plugin and a VNA plugin, generate a pattern and run a short scan.

4.2  The three removed helpers in gui/ui_modern.py (set_plugin_status, set_mode,
     set_dot) are documented as being "called from MainWindow". No such call
     exists today. If you were mid-way through wiring ui_modern.py up to
     MainWindow, restore them with:
         git checkout master -- gui/ui_modern.py
     and re-apply only the import cleanup.

4.3  Nothing under "Scanner App V1/" was modified. That frozen build still
     contains the pre-cleanup code, including the duplicate AxisInsn class.
     Rebuild it from this branch when you next ship.

4.4  gui/ui_scanner.py and gui/ui_scanner_plotter_version.py still carry ~24
     unused imports each. Those come from pyside6-uic and will return on the
     next regeneration; fix them in the .ui workflow, not by hand.
